# 动效走「令牌 → 角色 → 原语」三层，并用静态门禁约束

组件的动效参数一旦散落在各处，每次调观感都要翻十几个文件，改一处还会让相邻动效漂移（同一类进入动画三个不同数值的典型症状）。我们决定：所有动效数值集中在 `motion.config.json` 的 `tokens`（原子取值），语义写在 `roles`（只引用令牌名），组件通过 `motion-hooks.ts` 的原语按角色名消费；并用 `npm run lint:motion` 拒绝组件里的手写 `duration / ease / stiffness`，存量逐条进白名单且只许减。

## Considered Options

- **只写文档约定**：零成本，但我们已经有过 65 处散落参数，约定显然没拦住。
- **自动推断动效**（体系替组件挑角色）：少写代码，但会变成没人敢改的黑箱，且推断错的概率不低。
- **直接给组件传参数**（现状）：灵活，但"同一角色不同数值"的漂移正是要消灭的东西。

## Consequences

- 改观感 = 改一次 JSON；改错会被 `motion-system.test.ts`（角色→令牌引用、reduced 语义）挡住。
- 新增一类交互要多写两行（roles 条目 + ROLE_IDS），换来的是它自动获得 full/reduced 两档语义。
- 白名单是技术债账本：失效条目与超上限都会让门禁报错，所以它只会缩不会涨。
